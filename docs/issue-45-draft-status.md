## Compatibility and recovery

This is the breaking plugin-first cutover, not a dual runtime. Recognized legacy
lock rows upgrade only on an explicit writer mutation. Unsupported versions,
unknown fields and unsupported typed facts must fail before publication and
retain the original bytes. SQLite future versions must be rejected before WAL
configuration or writes. Plugin rollback restores content, not revoked grants;
database, plugin and binary rollback are distinct operations. Historical missing
implementations must block execution while preserving supported inspection; they
must not be substituted with a newer plugin. Final migration/backup/upgrade
results remain required before readiness.
The managed Registry static-reason variant is now `PluginRegistryStaticReason.NoStaticReason`;
all callers must migrate from the removed ambiguous `None` variant. No alias or
legacy constructor/runtime fallback is retained.

Unsafe writer ancestors retain the existing `plugin.lock_write_failed` error
classification for Native ENOTDIR/ELOOP rejection. Read-only fence errors keep
their existing classification. The fence still rejects before external plugin
directories are created; no Native path guard or installed SDK is changed (E68).
