# Managed Task execution source

Status: external candidate, authored but not compiled or executed. This increment extends the already captured managed-launch foundation. It does not complete Shell background execution.

The original foreground Operation must finish with its exact canonical launch result and completed Receipt before its one-shot reservation can be claimed. The same Runtime creates a separate Task Thread/Run with a canonical SystemNote, then commits one Task-source ToolCall. There is no model Decision, invented user message, HostService source, new database, or additional scheduler.

`ManagedJobAdmission` is constructed only by the live reservation. `DirectCallOrigin.ManagedJob` is descriptive persisted evidence; decoding it cannot recreate the live admission. The source binds the original parent Thread/Run/epoch/Operation/Item/call, the entire encoded normalized plan digest, service binding digest, permission domain, child identities and deadline. The Task owner permits no model context, new delegation, recovered attestation or second canonical root call.

`ToolPipeline.prepareManagedJob` uses that actual source to select the parent's current scoped contribution while keeping the child Thread/Run identity in execution and cancellation. It validates the original capability domain, exact current implementation/schema/version and full frozen plan. It does not rerun the plugin canonicalizer or fabricate another approval. Ordinary child Thread lookup cannot see the parent's scoped directory, and a borrowed snapshot cannot open this path. The Product authority hash helper now delegates to the identical generic ToolRuntime implementation; its encoding is unchanged.

SQLite admission, execution, handoff and settlement reconstruct the completed parent proof and one-shot claim from the existing audit and Operation tables. The Task origin gets its own immutable audit witness. Its normalized plan must equal the original plan byte for byte. Derived writes remain single-level ParentIntent children of the actual Task root. Primitive-ID entry points, source downgrade, epoch drift, changed calls and changed plans fail closed. Root/child settlement after cancellation can discharge already handed-off uncertainty without granting more I/O; the successful foreground launch remains a separate fact.

Authored validation: 38 real SQLite scenarios (19 each from Direct and Committed launches), plus 9 ToolPipeline/real Runtime seal scenarios using an explicitly non-durable Memory port. All are wired into existing full contract entry points. None has been compiled or run in this candidate. Static patch application and byte hashes are not runtime evidence.

Still required in the next increment: existing ProductTaskRuntime child-budget/journal/worker ownership; exact original service/lease delegation; SDK-declared host `preparation_ref` using all four original identity fields; native endpoint cache validation; actual Shell process/approval/cancellation/Product contracts. No plugin gets a generic ability to select another Thread. No automatic restart or replay is provided for recovered unfinished tasks. The original Shell path is retained until parity and real integration tests pass.
