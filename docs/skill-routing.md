# Installed Skills context

The Coding distribution installs and enables the independent Skills package through the normal plugin registry. Its versioned `plugins/context.json` selection binds the installed package digest and contribution. Existing user packages, explicit disablement and existing operator context configuration are preserved. A disabled or missing selected provider produces a typed inference error; it does not prevent plugin management or silently invoke a legacy Skills implementation.

`Product.request` accepts an immutable generic context projection or schedules the configured provider through the same Run. It performs no Skills filesystem discovery. A host without a configured context provider has no implicit Skills fallback. The generic Core, Runtime, Store and ToolInvocationContext do not depend on concrete Skill types. The standalone `agent_skills` package remains only for historical codec/library contracts.

For filesystem sources, metadata index/header reads and selected-body reads have canonical ContextRead Items, Operations, approvals, one Run budget and retained fact links. Headers stop at the closing delimiter; instruction bodies and references are not read during metadata discovery. Metadata source order, Pi selectors/globs/negations, explicit marker boundaries, deterministic automatic selection and rendered metadata limits live in `plugins/skills/src`. An accepted context update becomes visible only at the existing safe cut. Already prepared operations keep their original projection. Cancellation, invalidation or failed required context preparation cannot be treated as a successful update.

References are declared in the immutable context snapshot and loaded through `read_context_resource`. A historical declaration is not continuing permission: every lazy read uses the current Run, canonical parent, capability ceiling, policy and a new verified fact. Installed historical package content remains content-locked through update/uninstall and ordinary registry retention. Tool results do not mutate the context snapshot.

Validation is divided deliberately: the independently built Skills package runs 16 migrated pure algorithm cases and 37 packaged protocol cases; Product tests exercise normal Coding installation, the actual Run/Store read path and historical references. `product_prompt_contract` receives a real distribution via `AXYNDRA_CODING_DISTRIBUTION`. Its fixture is made with `scripts/prepare_coding_distribution_fixture.py --package <verified-package>`, using the normal distribution manifest and recipe. These migrated Cangjie cases are authored and must run in the integration graph; source migration alone is not parity evidence. Extreme Pi directory traversal, aggregate limits and the broader A5 acceptance matrix remain separately tracked.
