Continuation document observation
=================================

This candidate remains held for the complete document consumer graph. No
Cangjie compilation or integration execution is claimed by its static seal.

An actual Application user Command may freeze a same-package pure Provider
selector alongside a continuation control. The retained owner, original prompt,
accounting event, generation, budget and operator document read grant remain
mandatory. Neither an observation DTO nor a copied audit/Run creates an owner.
Controls without a selector retain the original strict document version pin.

Before another Run, the host reads a contiguous chain of completed canonical
document CAS operations. It verifies the original user document and every CAS
since its private watermark, including parent/child plans, reserved Receipts,
parent ToolResult, handoffs, source and ContextRead facts. Missing, duplicate,
foreign-scope or repository-only mutations stop the owner. Each intermediate
document must pass the pure restrict-only predicate using the same frozen time
and token statistics. A false answer or any failure permanently stops this
owner. A later active document cannot hide an earlier pause or completion.

The watermark advances only after the exact previously consumed admission's
Run completes. It advances to that admission's frozen observed endpoint, never
the latest version when its Run finishes. Mutations produced by that Run remain
in the next suffix. Each suffix includes its anchor and is limited to 256 CAS
observations; this is not a lifetime mutation counter. A failed/cancelled or
unknown Run does not advance the watermark. Final admission rechecks the exact
original pin, previous claim anchor and suffix in the existing transaction that
consumes the claim and creates the Run, Turn, SystemNote and Thread revision.

SQL reads measure returned byte lengths before copying raw strings across the
FFI. Raw data and aggregate decoded nodes share the existing native payload
owner pool. At most 16 MiB of cumulative returned bytes and 65,536 decoded nodes
fit one observation scope; actual aggregate pool availability may reject sooner.
An original-document lease remains with its owner, and each suffix lease remains
until its actual consumer completes. Revocation waits for active preparation
and admission consumption to exit before releasing retained data. Admission
verification has a separate temporary lease in the same pool, never a new pool.

The complete preparation has one monotonic five-second window, shortened by
the frozen request's wall/deadline limit. Every query receives only remaining
time; no predicate refreshes the window. SQLite steps and decoding check that
window cooperatively. No plugin runs while a database or runtime lock is held.

This first companion observes inline v1 document plans/results. The independent
Docs v2 history helper and shared allocator export must be integrated before the
complete graph can run. The existing pure query envelope is at most 4 MiB; raw
8 MiB document compatibility is not established by this candidate. Tree/byte
bounds and the overall observation deadline can reject a large suffix. The pure
Goal predicate's local accounting refresh does not persist Goal display state;
legacy writer retirement and display/accounting parity remain separate work.

Authored validation comprises four Domain codec cases, three Store allocation
cases (including actual SQLite metadata/invalid-UTF-8 ordering), and eight
Product/App cases with real installed workflow processes and canonical SQLite
facts. All fifteen are unrun at seal time. Static SQL/exact-apply checks do not
substitute for those contracts.
