Memory tools are published by the installed Native package as
`plugin.<namespace>.retain`, `.recall`, `.reflect`, `.memory_edit`, `.learn`,
`.manage_skill`, and `.memory_context`. Clients and model metadata must select
that actual name before ToolRoot admission. No old bare-name factory remains.

The operator document profile explicitly binds current package digest,
per-tool rights to logical key `journal`, `prepare_document`, ordinary payload
limits, payload references, and the fixed `opaque-fact-events-v3` backend.
`effect_from_intents` is optional: when true, a fully frozen read-only intent
plan can be classified read-only; invalid or changed plans stay conservative.
Neither this profile nor a Native envelope grants a Source or read capability.

The opt-in typed `memory_context` contribution accepts the exact
`axyndra.memory-context-query/v1` query with `query` and `max_bytes`. The Host
adds its real observed fact and current provider description. Returned content
is untrusted. Optional `valid_until_millis` restricts its usable lifetime and
must be checked by the generic Host/Core consumer; omitted means unbounded.

Current source-only candidate is not a completion claim. Large full-history
transport, actual payload context reads, managed-skill Workspace effects,
process interruption/recovery, and complete default-distribution assembly still
require implementation and acceptance evidence. The original business source
and all old cases remain explicit test-only oracles; they grant no authority.
